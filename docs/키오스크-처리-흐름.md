# 출결 키오스크(attendance_kiosk.html) 처리 흐름

이 문서는 출결 키오스크 웹앱(`attendance_kiosk.html`)이 `list-students`/`kiosk-checkin`
Edge Function과 어떻게 통신하는지 정리합니다. (v2.5.2 "키오스크 요청 정보 우선 처리",
v2.5.3 "키오스크 등하원 전송내역 표시" 반영)

## 1. 로그인 시 최소 목록 캐시 (v2.5.2)

예전에는 등원/하원 버튼을 누를 때마다 `kiosk-checkin`이 학생(학원) DB 전체를 조회해서
전화번호를 대조했습니다. 학생 수가 많아지면 버튼 한 번 누를 때마다 매번 전체 스캔이
발생해 응답이 느려집니다.

v2.5.2부터는 로그인 성공 시(그리고 그 뒤 5분 TTL마다) 화면이 다음 엔드포인트로
"최소 목록"을 한 번 받아 메모리에만 들고 있습니다.

- `GET /functions/v1/list-students?kiosk=1`
- 응답: `{ candidates: [{ registrationId, studentName, className, phones: [...] }], generatedAt }`
- 포함하지 않는 값: 출석 이력, 보고서 토큰, 보호자 이름 등 — 키오스크 화면에 필요 없는 값은
  최소 목록에서 아예 빼서 payload를 가볍게 유지합니다.
- 대상: "수강상태"가 🟢 수강 중인 등록만, 학생정보 relation이 정확히 1건으로 연결된
  경우만 포함합니다(공용 `kioskIdentity.ts`의 `buildKioskDirectory`).

화면(`attendance_kiosk.html`)의 캐시 동작:

- `kioskCandidatesAt` 기준으로 5분(`KIOSK_DIRECTORY_TTL_MS`)이 지나면 다음 등원/하원
  클릭 시 자동으로 다시 받아옵니다.
- 동시에 여러 번 호출되지 않도록 `kioskDirectoryPending`으로 중복 요청을 합칩니다.
- 로그아웃하거나 로그인 키가 바뀌면 `clearKioskDirectory()`로 캐시를 완전히 버립니다
  (다른 관리자 키로 전환됐는데 이전 캐시가 남는 것을 방지).
- 전화번호를 입력하고 등원/하원을 누르면, 먼저 캐시된 목록에서 번호가 일치하는 후보를
  찾습니다(`matchingKioskCandidates`). 캐시가 아직 없거나 일치하는 후보가 없으면 캐시를
  한 번 강제 새로고침(`refreshKioskDirectory(true)`)해서 다시 찾습니다.
- 후보가 여러 명이면 기존과 동일하게 선택 화면을 보여주고, 정확히 1명이면 그 등록 ID를
  요청에 실어 보냅니다. 캐시 자체를 못 받아온 경우(네트워크 오류 등)는 등록 ID 없이
  예전처럼 서버가 직접 조회하도록 보냅니다(하위 호환, 구버전 동작과 동일).

## 2. 서버 측 재검증 (v2.5.2)

클라이언트가 보낸 `registrationId`는 **힌트일 뿐**이며, `kiosk-checkin`은 이를 그대로
믿지 않고 매 요청마다 다시 검증합니다(`kioskIdentity.ts`의 `resolveKioskHint`):

1. 등록 페이지를 다시 조회해서 실제로 등록(학원) DB 소속인지 확인합니다(캐시가
   오래되어 다른 DB/삭제된 페이지를 가리키는 경우 방지).
2. 페이지가 보관함(archived/휴지통)에 있으면 무효 처리합니다.
3. "수강상태"가 여전히 🟢 수강 중인지 다시 확인합니다(그 사이 종료 처리됐을 수 있음).
4. 학생정보 relation이 정확히 1건인지, 그 학생 페이지가 실제 학생(학원) DB 소속인지
   확인합니다.
5. 그 학생의 연락처(학생/어머니/아버지/기타 보호자) 중 하나가 요청한 전화번호와
   실제로 일치하는지 다시 비교합니다.

위 중 하나라도 실패하면 등록 ID 힌트를 버리고, HTTP 409와 함께
`{ refreshCandidates: true, error: "학생 목록이 변경되었습니다. 다시 선택해주세요." }`를
반환합니다. 화면은 이 응답을 받으면 캐시를 무효화하고 최신 목록으로 다시 후보를
찾아 보여줍니다(그래도 없으면 오류 메시지 표시). 등록 ID 힌트가 애초에 없었던
요청(구버전 호환 경로)은 예전처럼 전화번호로 전체 학생을 다시 조회합니다.

이 재검증 덕분에, 캐시가 최대 5분까지 오래됐더라도(수강 종료 처리, 연락처 변경 등)
실제 출결 기록/알림톡 발송은 항상 최신 상태 기준으로 이뤄집니다.

## 3. 등원·하원 전송내역 표시 (v2.5.3)

출석(학원) DB의 "전송 내역" 수식은 그동안 "키오스크 알림톡" 발송 건에 대해서도 다른
보고서 발송과 똑같이 "담당자 미기록"이라고 표시했습니다(키오스크는 발송자가 사람이
아니라 자동화이기 때문). 실제로 등원인지 하원인지가 전송 내역에서 보이지 않아
담당자가 헷갈릴 수 있었습니다.

- 자동화 로그(학원) DB에 **"출결 구분"** select 속성을 추가했습니다
  (옵션: 등원/초록, 하원/파랑). 키오스크 알림톡 로그에만 채워지며, 다른 발송
  종류(일일/주간/월간 보고서, 수강료·교재비 안내 등)는 비워둡니다.
- `kiosk-checkin`이 전송로그를 남길 때(성공/실패 모두) 이 속성에 "등원" 또는 "하원"을
  함께 기록합니다.
- 출석(학원) DB의 "전송 내역" 수식을 수정해서, 가장 최근 로그가 "키오스크 알림톡"이면
  발송자 이름 대신 "등원"/"하원"(출결 구분이 비어 있는 과거 로그는 "등하원")을
  표시합니다. 그 외 발송 종류는 기존과 동일하게 발송자 이름 또는 "담당자 미기록"을
  표시합니다. 실패 로그도 동일한 규칙으로 "❌ 등원 실패 (...)" 처럼 표시됩니다.

## 참고

- 두 패치 모두 DB 스키마 추가/수식 변경 외에 별도 마이그레이션이나 Secrets 변경은
  없습니다.
- 실제 키오스크 기기에서의 등원/하원 동작과 카카오 알림톡 수신 여부는 배포 후
  운영자가 직접 확인해야 합니다(이 문서/코드 리뷰만으로는 실제 발송 성공을 보장하지
  않습니다).
